# 사건 상세 · 검토 워크플로 최종 설계도 (미니멀 개정판)

> 대상: 사건 관리 > 사건 상세 페이지 (`/cases/[id]`)
> 원칙: **기존 3패널 레이아웃과 하단 바는 그대로 유지**하고, 검토 관련 UI만 재배치한다.
> 핵심 규칙 하나 — **"할 일(행동)은 하단 바에, 상태는 헤더 칩에."**
> 색상: emerald(초록)·amber·red만 사용. 검토 UI에 파랑 계열 금지.

---

## 0. 색 시스템 (Tailwind 기준)

| 역할 | 값 |
|---|---|
| 완료·승인·진행 상태 | `emerald-700` 텍스트 / `emerald-50` 배경 / `emerald-200` 테두리 |
| 대기 상태 (배정대기 등) | `amber-700` / `amber-50` / `amber-200` |
| 위험·반려·불일치 | `red-700` / `red-50` (기존 그대로) |
| 주 액션 버튼 (결과보기) | 기존 다크 (`slate-900`) 유지 |
| 보조 액션 버튼 (검토 요청 등) | 텍스트 `slate-700` + 테두리 `slate-300` (테두리형) |
| 진행 도트 | 완료 `emerald-600` 채움+✓ / 현재 `amber-600` 테두리+숫자 / 미도달 `slate-100`+`slate-400` |

## 1. 삭제·수정 목록

1. **"사건 검토" 배너 카드 완전 삭제** (축소가 아니라 제거 — 검토 상태는 §2 칩으로)
2. 상단 영문 상태 칩 `COMPLETED` → 한글 `분석 완료` (emerald)
3. 뷰어 세션 만료 에러 문구 교체:
   - "세션이 만료되어 재생할 수 없습니다"
   - **[비밀번호 재인증] 버튼**을 에러 화면 안에 배치
   - 보조 문구 "재인증 후 자동으로 이어서 재생됩니다"
   - "step-up", "stream token" 등 기술 용어 삭제
4. 사건 제목이 sticky 헤더에 가려지는 문제: `scroll-margin-top` 보정
5. 그 외 요소(증거 목록, 뷰어, 메타데이터/코멘트 탭, 하단 바 위치)는 **변경 금지**

---

## 2. 헤더 = 상태 칩 영역

제목 줄 우측에 칩 나열:

- `분석 완료` (emerald) — 분석 중이면 `분석 중 N건`
- 검토 상태 칩 (검토 요청 이후에만 존재):
  - `검토 · 배정대기 ▾` (amber)
  - `검토 · 진행 중 · ○○○ ▾` (emerald)
  - `검토 완료 ▾` (emerald)
  - `보완 요청됨 ▾` (red)

### 검토 칩 클릭 → 팝오버 (폭 ~280px)
1. 미니 진행 도트 4개: 요청 접수 → 검토자 배정 → 검토 진행 → 검토 완료
2. 현재 단계명 + 안내 한 줄
   - 배정대기: "기관 관리자가 검토자를 배정하면 알림을 보내드립니다. **지금 하실 일은 없습니다.**"
   - 진행 중: "담당 ○○○ · 시작 07.15"
   - 보완 요청됨: 반려 사유 요약 + [상세 보기]
3. 하단: "요청 07.02 16:53 · 김민희"
- 외부 클릭/Esc로 닫힘. 팝오버 외 검토 정보를 본문에 상시 노출하지 않는다.

---

## 3. 하단 바 = 행동 영역 (역할별)

하단 바 구성: 좌측 `+ 증거 추가` / 우측 버튼 그룹 (보조 → 주 순서)

| 역할·상황 | 하단 바 우측 |
|---|---|
| 분석관 · 검토 요청 전 | `검토 요청`(보조) + `결과보기`(주) |
| 분석관 · 요청 후 | `결과보기`만 (검토 요청 버튼은 칩으로 "변신") |
| 분석관 · 반려됨 | `보완 완료 · 재검토 요청`(보조) + `결과보기`(주) |
| 기관 관리자 · 배정 대기 | `검토자 배정`(보조) + `결과보기`(주) |
| 검토관 · 검토 진행 | `보완 요청`(red 테두리) + `검토 승인`(emerald 테두리) + `결과보기`(주) |

- **버튼 ↔ 칩 전환 규칙**: 행동이 완료되면 하단 버튼이 사라지고 헤더 칩이 갱신된다.
  화면에 검토 요소는 항상 "버튼 하나" 또는 "칩 하나"만 존재.
- `검토 요청` 활성 조건: 모든 증거가 분석 완료 상태일 것.
  미충족 시 비활성 + 툴팁 "모든 증거 분석 완료 후 요청할 수 있습니다".

### 확인 모달 (분석관 · 검토 요청)
- "기관 관리자에게 검토를 요청합니다." (+ 요청 후 증거 수정이 잠긴다면 그 안내 1줄)
- 버튼: [요청] / [취소] — 검토자 선택 UI 없음 (분석관은 선택하지 않는다)

### 배정 모달 (관리자 · 검토자 배정)
- 검색 입력 + 검토관 리스트: 이름 · 전문분야 태그 · 소속 ·
  **진행 중 건수** (4건 이상 red 강조) · 평균 소요일
- 재검토(2차) 배정 시 이전 검토관 기본 선택
- 확인 버튼 문구: `"○○○에게 배정"` (구체적으로)

### 검토관 화면 하단 바 상세
- 버튼 순서 (좌→우): `결과보기`(테두리) → `보완 요청`(red 테두리) → `검토 승인`(emerald 채움)
  — 검토관 화면에서는 판정이 주 액션이므로 승인이 유일한 채움 버튼
- 하단 좌측: `+ 증거 추가` 대신 **열람 카운터** "증거 9개 중 7개 열람"
  (검토관에게 증거 추가 권한 없음)

### 판정 모달 (검토관)
- `검토 승인` 모달:
  - 사건 요약 1줄 + **미열람 가드**: 안 본 증거가 있으면 amber 경고
    "⚠ 아직 열람하지 않은 증거가 N건 있습니다 (증거 5, 6)" — 차단하지 않고 표시만
  - 의견 입력 (선택) + 고지 "확정 후에는 취소할 수 없으며, 검토 기록에 영구 저장됩니다."
  - 버튼: [취소] / [승인 확정](emerald)
- `보완 요청` 모달:
  - 안내 "분석관 ○○○에게 반려됩니다"
  - **사유 입력 필수** — 비어 있으면 전송 버튼 비활성 + "사유를 입력해야 보낼 수 있습니다"
  - 동일한 취소 불가 고지 + 버튼: [취소] / [보완 요청 보내기](red)
- 취소/Esc로 닫으면 아무 상태 변화 없음
- 판정·사유는 코멘트가 아닌 **검토 회차 기록**에 저장 (수정 불가)

### 판정 확정 시 동작 (동시에 3가지 — 버튼은 "숨김"이 아니라 제거)
1. 하단 판정 버튼 2개 제거 (결과보기만 남음)
2. 헤더 칩 갱신: `검토 완료`(emerald) 또는 `보완 요청됨`(red)
3. 코멘트에 시스템 이벤트 라인 자동 기록 + 분석관에게 알림
- 판정 취소 기능 없음 — 뒤집으려면 재검토 사이클(§4)로만

---

## 4. 재검토 (회차 누적 — 리셋 금지)

- 반려 시: 헤더 칩 `보완 요청됨`(red) + 하단에 `보완 완료 · 재검토 요청` 버튼 재등장
- 재검토 요청 시 2차 사이클 시작 (같은 4단계 도트)
- 이전 회차는 칩 팝오버 안에 접힌 기록으로 보존:
  `[1차] 보완 요청됨 · ○○○ · 07.16 "사유 요약" [상세 보기]`
- 회차 기록은 삭제·수정 불가 (감사 이력)

---

## 5. 코멘트 탭 (우측 패널)

- 판정(승인/보완) 버튼을 코멘트 영역에서 **완전히 제거** (§3 하단 바로 이동)
- 유지·보강:
  1. **역할 배지**: 작성자 이름 옆 `분석관` / `검토관` 배지
  2. **증거별 스레드**: 현재 선택된 증거에 대한 대화만 표시
  3. **시스템 이벤트 라인**: 판정 발생 시 자동 삽입
     `⚑ ○○○님이 보완을 요청했습니다 · [1차 검토 의견 보기] · 07.16` (회색 배경 1줄)
- 라벨은 "메모"가 아니라 "코멘트"
- CoC는 기존대로 무결성 검증 → 상세 경유 (탭 추가 금지)

---

## 6. 알림 연결

- 배정 완료 → 분석관·검토관 / 판정 → 분석관 / 재검토 요청 → 관리자
- 알림 클릭 시 해당 사건 상세로 이동 (헤더 칩+팝오버가 상태를 설명)

---

## 7. 접근성

- 검토 칩: `aria-expanded` + 팝오버 `role="dialog"`, Esc 닫기, 포커스 트랩
- 진행 도트: 색만으로 구분 금지 — ✓/숫자 병기, 팝오버에 단계명 텍스트
- 판정 모달: 사유 필수 검증 메시지를 스크린리더에 전달 (`aria-describedby`)
- 상태 칩: 색 + 텍스트 이중 표기

---

## 8. 금지

- 검토 배너(전폭 카드)의 부활 — 어떤 형태로든
- 검토/스테퍼 UI에 파랑 계열 사용
- 판정 버튼을 코멘트 영역에 배치
- 분석관에게 검토자 선택 UI 노출
- 재검토 시 이전 회차 기록 삭제·리셋
- 3패널 레이아웃·하단 바 위치 변경, 새 문구 창작
